# 传统自动指标（BLEU / ROUGE / METEOR / BERTScore）

## 这是什么（定义）
LLM-as-a-Judge 出现之前的自动评估方法，核心思路是**把"候选回答"与"参考答案"做相似度比较**：
- **BLEU**：n-gram 精确匹配（机器翻译常用，衡量"召回不足、精度优先"）。
- **ROUGE**：n-gram 召回（摘要常用）。
- **METEOR**：在词形/同义层面松弛匹配。
- **BERTScore**：用预训练模型向量做语义相似（比词面略强，但仍要求"一稿对一稿"）。

## 通俗直觉
"参考答案里有这些词，你的答案里有几个？"——数词的重合度。它本质上假设"好答案≈参考答案的改写"，对开放式任务（多种说法都对）很脆弱。

## 数值/结果怎么读
- 它们在[本调研中的角色]：几乎只作为**背景/对照**出现，只有 [2503.05061] 做了数值对比（金融正确性任务上 BLEU/ROUGE/METEOR 的一致性远低于 LLM judge [Table 7, Appendix E.2]）。
- 词法指标整体上 < 嵌入相似度 < 奖励模型 < "LLM judge + Human 参考"（[2503.05061] Appendix E）；无参考的 LLM judge 有时只和它们打平，甚至更差。

## 为什么重要（隐藏含义）
- 它们证明了"为什么要引入 LLM judge"：开放式任务上词面重叠完全失效。
- 但它们也留下了一个**参照系**：评测"LLM judge 到底有没有用"，最好的方式就是和这些廉价基线比——如果 judge 连 BLEU 都赢不了，它的价值就要打个问号（这正是 [2503.05061] 的对比策略）。
